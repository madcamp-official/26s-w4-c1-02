# 데모 시나리오 (G5 발표)

기획 의도의 문장을 **데모가 그대로 되받는** 구성이다. 각 시나리오는 인트로 카피의 한 문장을 집고,
화면으로 그 문장을 뒤집는다. 전부 지금 프로덕션(endpointer.madcamp-kaist.org)에서 실제로 도는 것만 쓴다.

발표 순서 제안: **① → ② → ③ → ④ → ⑤** (비개발자 서사 → 개발자 서사 → 살아있음 → 확장).
시간이 밀리면 ⑤부터 자른다. ①과 ③은 자르지 않는다 — 이 둘이 기획서의 "조잡하면 안 되는 둘"(접합·치유)이다.

---

## ① "어느 화면에도 존재하지 않는 조건"을 화면으로 만든다

> 카피: *"세 사이트를 통틀어 마감이 일주일 남은 것" 같은 조건은 어느 화면에도 존재하지 않습니다.*

**대상**: 비개발자 서사. 발표의 척추 — 여기서 제품이 무엇인지 다 보인다.

**무대**: 창업지원 공고 2~3곳 (리허설로 검증된 사이트 사용 — K-스타트업 + 기업마당 조합 권장).

**진행**:
1. 새 컬렉션 → 주소 붙여넣고 **담기** → 만들기. "우리가 사이트에 요구한 건 주소 한 줄입니다."
2. 이미 채워진 표가 뜬다 (B3). 열 하나 ✕로 지우는 것까지 보여준다 — "설정이 아니라 편집입니다."
3. 두 번째 사이트 붙이기 (기능②). 못 찾은 칸이 나오면 **값을 복사해 붙여넣는다** (B1) —
   "셀렉터를 배우는 게 아니라, 화면에 보이는 값을 알려주면 시스템이 역추적합니다."
4. 표 탭에서 필터: 마감 **7일 이내** → **"이 조건 저장"** → 뷰가 된다.
5. 펀치라인: **"방금, 어느 화면에도 없던 조건이 화면이 됐습니다. 그리고 이 화면은 내일도 스스로 갱신됩니다."**

**준비물/리스크**:
- 생성은 LLM 컴파일을 타므로 수 초~수십 초. **발표 직전 같은 주소로 한 번 돌려 캐시를 데워 둔다** (두 번째는 거의 즉시).
- 접합 실패 백업: 미리 접합까지 끝낸 동일 컬렉션을 준비해 두고 "시간 관계상 완성본으로 보겠습니다"로 전환.

## ② "매주 청구되는 비용"을 알림으로 끊는다

> 카피: *정보는 무료인데, 접근하는 비용은 매주 청구됩니다.*

**대상**: 비개발자 서사의 마무리. ①에서 만든 뷰를 그대로 이어 쓴다.

**무대**: ①의 "마감 7일 이내" 뷰 + **디스코드 웹훅** (심사위원들이 아는 물건).

**진행**:
1. 뷰에 알림 켜기 → 웹훅 주소 붙여넣기.
2. 디스코드 채널 화면 전환 — **이미 도착해 있는 알림** (전날 수집분)을 보여준다.
   항목 제목·마감·원문 링크가 그대로 온다.
3. 펀치라인: **"매주 이 페이지들을 다시 여는 사람이 이제 없습니다. 조건에 걸리는 것이 생기면, 그쪽에서 옵니다."**

**준비물/리스크**:
- 알림은 수집 주기에 걸려야 오므로 **라이브로 발송을 유도하지 않는다.** 전날 도착해 둔 알림 + 타임스탬프가 증거다.
- 여흥용 훅(선택): 메가박스 컬렉션 "새 영화가 예매 목록에 뜨면 알림" — "영화 예매 오픈봇, 이 제품에선 뷰 하나입니다."

## ③ 개발자 서사 — 인프라를 안 만들었는데 API가 있다

> 카피: *만들려던 것은 그 데이터를 쓰는 기능이었는데, 데이터를 공급하는 인프라를 먼저 만들게 됩니다.*

**대상**: 개발자 서사. 라이브 코딩 1분.

**무대**: ①의 컬렉션. 연결 탭의 주소 한 줄.

**진행**:
1. 연결 탭 → `GET https://endpointer-api.madcamp-kaist.org/{slug}` 복사.
2. 터미널에서 `curl … | jq '.items[0]'` — 정규화된 JSON. "날짜는 ISO, 금액은 숫자입니다. 세 사이트가 제각각 적은 걸 시스템이 맞췄습니다."
3. `?view=마감임박뷰` 붙이기 — **뷰가 곧 쿼리다.** 화면에서 저장한 조건이 API 파라미터로 그대로 존재한다.
4. 미리 짜둔 **30줄짜리 D-day 위젯** (fetch 한 번 + map)을 띄운다.
5. 펀치라인: **"수집기, 정규화, 저장, 스케줄러, 인증 — 하나도 안 만들었습니다. 만든 건 이 30줄, 데이터를 '쓰는' 코드뿐입니다."**
6. (시간 되면) MCP 한 줄을 Claude 커넥터에 붙이고 "마감 임박한 것 요약해줘" — 같은 뷰가 AI 도구로도 존재한다.

**준비물/리스크**: 위젯은 사전 작성·검증. MCP 장면은 네트워크 의존이라 스크린샷 백업.

## ④ "조용히 무너진다"의 반대를 보여준다 — 자가 치유 (기능④)

> 카피: *사이트가 클래스 이름 하나만 바꿔도 조용히 무너집니다. 빈 결과가 돌아오고, 로그에는 정상으로 남습니다.*

**대상**: 두 서사의 합류점. 이 제품의 "계속 살아있게"가 말이 아님을 증명.

**무대**: 두 가지 방식 중 리허설에서 안정적인 쪽 (A와 조율):
- **방식 A (라이브)**: 로컬 픽스처 사이트의 마크업을 그 자리에서 바꾸고 수집 → 감지 → 재컴파일 → 복구까지 돌린다.
- **방식 B (기록)**: 프로덕션 대시보드의 **자동 복구 기록** ("이번 달 자동 복구 N회")과 소스 상태 줄을 보여준다.

**진행** (방식 B 기준):
1. 대시보드의 "자동 복구 N회" 지표를 짚는다.
2. 소스 카드의 상태 문구 — "다시 맞추는 중" → "연결됨" 전환 이력.
3. 펀치라인: **"사이트가 바뀌는 걸 막을 수는 없습니다. 우리가 막는 건, '조용히' 무너지는 것입니다. 무너지면 감지하고, 고치고, 고쳤다고 기록합니다."**

**준비물/리스크**: 방식 A는 극적이지만 실패 리스크가 있다. 리허설에서 2회 연속 성공 못 하면 방식 B로 고정.

## ⑤ 창작마당 — 모으는 일을 "반복"하지 않는 마지막 조각

> 카피: *흩어진 것을 한 번 모으는 일이 아니라, 모아둔 것이 계속 살아있고 필요한 곳에서 꺼내쓸 수 있게 하는 일.*

**대상**: 확장 서사 + 데모 피날레. "필요한 곳에서 꺼내쓴다"를 사람 사이로 확장.

**무대**: ①에서 만든 컬렉션을 발표자 계정에서 **공개 + 창작마당 전시**로 켜 둔 상태. 두 번째 계정(또는 두 번째 브라우저).

**진행**:
1. `/gallery` — 전시된 컬렉션 카드 (원작자·항목 수·복제 횟수).
2. 다른 계정으로 **"이 컬렉션 복제하기"** → 몇 초 뒤 내 컬렉션이 된다. **표가 이미 차 있다** — 소스·뷰·항목이 통째로 왔다.
3. 복제본 대시보드의 배너: "○○에서 복제했어요 — **내가 아는 사이트 더하기 →**" 를 짚는다.
4. 펀치라인: **"이 사람은 모으는 일을 한 번도 하지 않았습니다. 남이 모아둔 위에서, 자기 것 하나를 더하는 것부터 시작합니다."**

**준비물/리스크**: 복제는 DB 복사라 빠르고 LLM을 안 탄다 (리스크 낮음). 두 번째 계정 로그인을 미리 해 둔다.
