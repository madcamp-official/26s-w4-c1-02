# 관문 체크리스트 G0~G5

> 기획서 13장을 체크박스로 옮긴 것. **하루의 시작에 다음 관문 조건을 소리 내어 읽고, 하루의 끝에 판정한다.**

## 판정 규칙 (기획서 13장)

- 작업량과 속도를 추정하지 않는다. 각 관문에는 **통과 판정 조건만** 있다.
- **관문은 말이 아니라 화면으로 판정한다.** 구두 보고가 아니라 실제로 돌려서 본다.
- 판정값은 **통과/미통과 둘뿐**이다. "거의 됨"은 미통과다.
- 미통과면 **그 자리에서** 강등 규칙을 발동할지 결정한다. 다음 관문으로 부채를 넘기지 않는다.
  강등은 실패가 아니라 설계된 경로다.
- 체크박스는 **직접 돌려서 눈으로 본 것만** 채운다. 코드가 있다는 것과 돈다는 것은 다르다.

| 관문 | 이름 | 한 줄 판정 | 시점 | 담당 |
|---|---|---|---|---|
| G0 | 계약 고정 | 가짜 데이터로 두 트랙이 서로를 안 기다린다 | Day 1 시작 | 공동 |
| G1 | URL 하나가 아이템이 된다 | 그 자리에서 정한 낯선 URL 에서 아이템이 나온다 | Day 1 종료 | A / B 각자 |
| G2 | 두 번째 소스가 붙는다 | 두 출처가 한 표에 같은 형식으로 섞인다 | Day 2 종료 | 합류 |
| G3 | 계속 돈다 | 일부러 깨뜨려도 혼자 고치고, 나머지는 산다 | Day 3 종료 | A / B 각자 |
| G4 | 배포 · MCP · 낯선 사람 | 도메인에서 처음 본 사람이 혼자 성공한다 | Day 4 종료 | 합류 |
| G5 | 데모 | 끊김 없이 한 번에 녹화된다 | Day 5 종료 | 공동 |

```
G0 ─┬─→ G1(A) ──→ G2 ──→ G3(A) ──→ G4 ──→ G5
    └─→ G1(B) ──┘        G3(B) ──┘
```

G2 와 G4 가 합류 지점이다. 이 두 곳에서만 서로의 결과물이 필요하고, 나머지는 G0 에서 고정한 계약으로 각자 간다.

## G0 — 계약 고정 (공동)

여기서 만든 계약이 남은 4일의 병렬성을 결정한다. **이 관문만은 둘이 같이 붙는다.**

### 타입 계약 — `packages/core`

- [x] `Collection` · `Source` · `Adapter` · `Item` · `Run` · `Subscription` 타입이 있다 (`src/types/*.ts`)
- [x] 어댑터 스펙 타입이 기획서 11장 그대로 있다 — json / html / browser 세 모드 (`src/spec/spec.ts`)
- [x] 변환 연산자가 **닫힌 집합**으로 정의돼 있고, 목록 밖 `op` 는 파싱 단계에서 거부된다 (`src/spec/ops.ts`)
- [x] 상태 값 집합이 한 군데에만 있다 — `SourceStatus` / `AdapterStatus` / `AdapterOrigin` / `RunStatus` / `FetchMode` / `Visibility` / `FieldType` / `SubscriptionChannel`
- [x] 스펙 해석기가 순수 함수다 — 네트워크를 타지 않고, HTML 평가는 주입점으로 받는다 (ADR A18)
- [x] 정규화 파서가 date / money / number / text / link / enum 여섯 타입을 처리한다 (`src/normalize/*`)
- [x] 정규화·연산자·해석기·검증기에 단위 테스트가 붙어 있다 (`src/**/*.test.ts`)
- [ ] `pnpm --filter @endpointer/core test` 가 실제로 통과한다 — **미확인**: 스캐폴딩에서 실행하지 않았다

### DB 와 시드

- [x] Drizzle 스키마가 기획서 10장의 테이블을 전부 담고 있다 (`src/db/schema.ts`)
- [x] 시드 스크립트가 컬렉션 1개 · 소스 2개 · 아이템 20개를 넣도록 작성돼 있다 (`src/db/seed.ts`)
- [x] 시드가 **멱등**하도록 작성돼 있다 — `UNIQUE (source_id, external_key)` + `onConflictDoUpdate`
- [ ] `pnpm db:generate` 로 마이그레이션 SQL 이 생성돼 있다 (`packages/core/drizzle/*.sql`)
      — **미확인**: 스캐폴딩에서 `pnpm` 실행이 금지돼 SQL 을 아직 뽑지 않았다. Day 1 첫 명령이 이것이다
- [ ] `pnpm db:migrate` 가 빈 DB 에서 끝까지 돈다 — **미확인** (위와 같은 이유)
- [ ] `pnpm db:seed` 를 **두 번** 돌려도 아이템이 20개다 — **미확인** (위와 같은 이유)

### 공개 API

- [ ] 시드 데이터로 `GET /api/v1/contest` 가 200 을 준다
- [ ] 응답에 `items` · `sources` · `schema_version` · `page` 가 **전부** 있다
- [ ] `sources` 가 옵션이 아니다 — 아이템이 0건인 소스도 키가 나온다 (원칙 ④ · ADR A4)
- [ ] 두 소스의 날짜와 금액이 **같은 형식**으로 나온다 (`20260814` 와 `~2026-08-21` 이 한 형식으로)
- [ ] 같은 응답을 만드는 코드를 web 과 mcp 가 공유한다 (ADR A22)

### 병렬성 — 이 관문의 존재 이유

- [ ] 트랙 B 가 트랙 A 의 코드 **없이** 화면을 만들 수 있다 (시드 데이터만으로 표가 그려진다)
- [ ] 트랙 A 가 트랙 B 의 화면 **없이** 파이프라인을 만들 수 있다 (해석기 테스트만으로 검증된다)
- [x] 트랙 경계가 디렉터리 경계와 일치한다 — `apps/worker`=A, `apps/web`·`apps/mcp`=B, `packages/core`=상호 통보

<details>
<summary><b>강등 규칙 — 없다</b></summary>

이 관문은 강등할 수 없다. 못 넘으면 넘을 때까지 둘이 붙는다.
**여기를 대충 넘기면 G2 합류에서 이틀치가 날아간다.**
</details>

## G1 — URL 하나가 아이템이 된다 (Day 1 종료)

### 트랙 A

- [ ] **판정하는 자리에서 처음 고른** 목록 URL 3개 중 최소 2개에서 아이템 5개 이상이 추출된다
      (미리 뚫어둔 URL 로 판정하지 않는다 — P2)
- [ ] probe 가 어느 경로로 뚫렸는지 로그에 구분돼 남는다: 인라인 JSON / 네트워크 관찰 / DOM 반복 구조 / 브라우저 렌더
- [ ] 추출된 필드에 타입이 붙는다
- [ ] 날짜가 정규화된 값으로 나온다
- [ ] 금액이 정규화된 값으로 나온다

### 트랙 B

- [ ] 구글 로그인이 된다
- [ ] 로그인 후 "내 컬렉션 목록" 화면이 있다
- [ ] 컬렉션 상세에서 시드 데이터가 표로 렌더된다
- [ ] 표에서 정렬이 동작한다
- [ ] 표에서 필터가 동작한다
- [ ] **B5 점검**: API URL 이 화면에 있되 접혀 있다 → [guardrails.md](./guardrails.md#b5)

<details>
<summary><b>강등 규칙</b> (트랙 A 미통과 시, 위에서부터 순서대로)</summary>

1. 브라우저 probe 를 뒤로 미룬다 — 인라인 JSON + 정적 HTML 만으로 G1 을 다시 판정
2. 그래도 미통과면 DOM 반복 구조 탐지를 버리고 인라인 JSON + 네트워크 관찰만 남긴다
3. 그래도 미통과면 대상을 미리 뚫어둔 3곳으로 좁히고, 임의 URL 은 화면에서 "실험" 상태로 표시한다
   (P2 후퇴 — 여기까지 오면 제품 주장이 약해지므로 **G5 발표에서 이 한계를 명시한다**)
</details>

## G2 — 두 번째 소스가 붙는다 (Day 2 종료 · 첫 합류)

**여기까지가 원 기획안의 v1 이고, 제품이 성립하는 지점이다.**

- [ ] 서로 다른 호스트 2곳의 아이템이 **하나의 표**에 섞여 나온다
- [ ] 출처 뱃지로 구분된다
- [ ] 두 번째 소스의 필드가 기존 스키마에 **자동으로 매핑**된다
- [ ] 못 찾은 필드만 사용자에게 물어본다 (전부 다시 묻지 않는다)
- [ ] 사용자는 **값을 붙여넣어** 그 필드를 해결한다 — 셀렉터를 입력하지 않는다 → [B1](./guardrails.md#b1)
- [ ] 날짜가 두 소스에서 같은 형식으로 나온다
- [ ] 금액이 두 소스에서 같은 형식으로 나온다
- [ ] 분류값 매핑이 동작한다 ("기술개발" 과 "R&D" 가 같은 값으로)
- [ ] `GET /api/v1/{slug}` 가 **실제 수집 데이터**로 응답한다
- [ ] 필터·정렬·페이지가 API 에서 동작한다
- [ ] `sources` 에 소스별 상태가 들어 있다
- [ ] 값에 마우스를 올리면 원문 조각이 보인다 (원문 대조)

<details>
<summary><b>강등 규칙</b></summary>

1. 자동 매핑의 확신도 기준을 낮춰 더 많이 시도하고, 틀리면 사용자가 고치는 경로를 넓힌다
2. 그래도 미통과면 자동 매핑을 포기하고 **전 필드를 붙여넣기로** 받는다
   (기능 ②의 주장은 약해지지만 "두 소스가 하나의 표"는 지킨다. **보장선 B1 은 유지된다**)
3. 원문 대조를 G4 로 미룬다 (마지막 수단 — 5장의 신뢰 계층이 약해짐)
</details>

## G3 — 계속 돈다 (Day 3 종료)

### 트랙 A — 자가 치유

- [ ] 스케줄 수집이 사람 손 없이 돈다
- [ ] 신규 항목이 기존 항목과 구분된다
- [ ] **두 번 연속 수집했을 때 두 번째의 신규가 0이다** (기획서 15장 `external_key` 불안정 리스크 대응)
- [ ] 소스 하나를 **일부러 깨뜨렸을 때** 검증이 그걸 잡아낸다
- [ ] 깨진 소스만 격리되고, **나머지 소스는 계속 정상 응답한다** (원칙 ④)
- [ ] 마지막 성공 데이터를 계속 서빙하되 `age` 를 표시한다
- [ ] 자가 치유 잡이 새 스펙을 만들어 재검증을 통과하면 **자동 승격**된다
- [ ] 이전 버전이 롤백 가능하게 남는다
- [ ] 컬렉션 화면에 "자동 복구 N회"가 보인다

### 트랙 B — 피드와 구독

- [ ] 읽기 피드 화면이 있다
- [ ] "새로 올라온 것"과 "마감 임박"이 구분된다
- [ ] 웹훅 구독을 걸면 **신규 항목만** 담긴 페이로드가 1회 전송에 성공한다
- [ ] 발송 채널이 인터페이스로 추상화돼 있다 (이메일 구현체를 추가할 자리가 비어 있다)
- [ ] **B4 점검**: 깨진 소스가 화면에서 빨간 에러가 아니라 상태 문구로 보인다 → [B4](./guardrails.md#b4)

<details>
<summary><b>강등 규칙</b></summary>

1. 자동 승격을 빼고 **감지 + 격리 + 사람 호출**까지만 한다. 재컴파일 버튼을 사람이 누른다
   (기능 ④의 절반. 화면 상태 표시와 "복구 N회" 로그는 유지 — 데모에서 보여줄 것이 남는다)
2. 그래도 미통과면 검증(드리프트 감지)까지만 하고 치유를 버린다.
   **이때 5장의 "사수해야 할 셋" 중 하나가 무너지므로, G5 발표에서 이 부분을 미완으로 명시한다**
3. 구독 쪽이 미통과면 스케줄 발송을 버리고 "즉시 발송"만 남긴다
</details>

## G4 — 배포 · MCP · 낯선 사람 (Day 4 종료 · 두 번째 합류)

- [ ] 도메인에 HTTPS 로 떠 있다
- [ ] 재부팅해도 컨테이너가 다시 뜬다
- [ ] **이 프로젝트를 모르는 사람**이 도메인에 접속해서 구글 로그인 → URL 2개 붙여넣기 → 컬렉션 생성 → 표 확인까지 **설명 없이** 도달한다 (한 명이면 충분하다 — P10)
- [ ] MCP 주소를 커넥터에 붙여넣으면 "이번 주 마감 뭐 있어?"에 실제 아이템으로 답한다
- [ ] 이메일 구독이 붙는다 (P7 의 후반)
- [ ] `pnpm --filter @endpointer/web test` 가 통과한다 (B2 금지 명사 자동 점검)
- [ ] **보장선 B1~B7 전수 점검. 하나라도 위반이면 미통과** → [guardrails.md](./guardrails.md)
      — 자동 점검은 B2 일부만 잡는다. B1·B3·B5·B6·B7 은 화면을 열어야 판정된다

<details>
<summary><b>강등 규칙</b></summary>

1. 이메일 구독을 버린다 (웹훅만 남김 — P7 의 "이어서"가 안 온 것)
2. MCP 를 배포된 HTTP 서버 대신 **로컬 stdio + 설치 안내 한 줄**로 낮춘다
   (보장선 B7 이 깨지므로 데모에서 개발자 경로임을 명시한다. **이건 뼈아픈 강등이다** —
   3장에서 MCP 를 가장 차별적이라고 했고 그 이유가 비개발자 접근이었다)
3. 낯선 사람 테스트를 통과 못 하면, 막힌 지점 하나만 고치고 **나머지 기능 작업을 전부 멈춘다**
   (보장선이 기능보다 우선한다 — 5장 냉정한 우선순위)
</details>

## G5 — 데모 (Day 5 종료 · 공동)

- [ ] **끊김 없이 한 번에 녹화한** 데모 영상이 있다 (편집으로 실패를 가리지 않는다)
- [ ] 영상에 표가 나온다
- [ ] 영상에 읽기·구독이 나온다
- [ ] 영상에 API 응답이 나온다
- [ ] 영상에 MCP 대화가 나온다
- [ ] 영상에 자가 치유가 나온다 (소스를 깨고 → 상태가 바뀌고 → 복구되는 장면)
- [ ] 발표 자료가 있다
- [ ] **강등한 것이 있다면 발표 자료에 숨기지 않고 적었다**

<details>
<summary><b>강등 규칙 — 없다</b></summary>

여기 도달하지 못하면 직전 관문 상태 그대로 녹화한다.
**없는 기능을 녹화 트릭으로 만들지 않는다.**
</details>
