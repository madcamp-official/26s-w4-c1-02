# 세상을 악기로 만드는 카메라 — 전체 논의 정리

몰입캠프 1주 프로젝트. 아이디어 탄생부터 D1 실행 계획까지의 모든 결정과 근거를 담은 문서.

---

## 0. 아이디어의 계보

1. **출발**: 영상 속 미세 진동을 증폭·활용하는 기법(복소 스티어러블 피라미드 기반)에서 "만질 수 있는 사진" 아이디어가 나옴 — 물체를 30초 찍으면 진동 모드를 추출해, 정지 사진 속 물체를 드래그하면 물리적으로 출렁이게 만드는 것.
2. **존재 체크에서 걸림**: 코어 인터랙션이 이미 존재.
   - MIT *Interactive Dynamic Video* (2015) — 영상에서 진동 모드 추출 → 드래그 인터랙션. 정확히 같은 파이프라인.
   - Google *Generative Image Dynamics* (2023) — 사진 한 장에서 학습 prior로 모션 생성, 드래그·릴리즈 반응. 웹 데모까지 공개됨.
   - 결론: 코어는 새롭지 않고, 제품화만 비어 있음. 몰입캠프 발표에서 심사위원이 구글 데모를 알면 임팩트 반감.
3. **피벗**: 재미 레이어 중 유일하게 아무도 안 건드린 자리가 **소리**. "만질 수 있는 사진"에서 **"세상을 악기로 만드는 카메라"**로 축 이동. 시각 인터랙션은 조연으로 내려가고, 실물에서 측정한 소리가 주인공이 됨.

## 1. 한 줄 정의

> **물건을 10초 찍으면, 그 물건이 화면 안에서 연주 가능한 악기가 된다.**

유리컵을 찍으면 화면 속 유리컵을 두드려 소리를 낼 수 있다. 입구를 치면 맑게, 바닥을 치면 둔탁하게 — 실제 그 컵과 같은 소리로. 채집한 물건들을 모아 합주하고, 링크 하나로 친구에게 보내면 친구도 내 컵을 연주할 수 있다.

**이 소리는 합성음이 아니라 그 물체에서 실제로 측정한 값이다.** 이것이 유일한 주장.

---

## 2. 기술 원리

### 2-1. 모달 합성

단단한 물체를 때렸을 때 나는 소리는 감쇠 사인파들의 합:

```
y(t) = Σᵢ  aᵢ · e^(−dᵢ·t) · sin(2π fᵢ t)
```

- **fᵢ (공진 주파수)**: 물체의 모양·재질이 결정. 음정과 음색.
- **dᵢ (감쇠 계수)**: 얼마나 오래 울리는지. 금속은 작고 나무는 큼.
- **aᵢ (진폭)**: **때린 위치에 따라 달라짐.** 마디(node)를 치면 그 모드는 안 울리고 배(antinode)를 치면 크게 울림. → 위치별 진폭 벡터가 "어디를 치면 어떤 소리"의 공간 지도가 됨.

(f, d, a) 삼중항 10~20개면 물체를 무한히 연주 가능. IRCAM Modalys 등 물리 모델링 신스가 같은 원리로 동작하지만, 이들은 3D 모델·재질 물성을 손으로 입력해야 함. **우리의 기여: 그 값을 실물에서 폰으로 직접 측정.**

### 2-2. 오디오/영상 역할 분담 — 가장 중요한 설계 결정

- 영상으로 볼 수 있는 진동: 프레임레이트 절반 한계. 240fps여도 실질 1~30Hz.
- 귀로 듣는 소리: 200~5,000Hz.
- **눈으로 보는 진동과 귀로 듣는 진동은 다른 모드다.** 보이는 진동을 옥타브 올리면 "그럴듯한 음색"일 뿐 그 물체의 진짜 소리가 아님.

| 신호 | 담당 | 대역 |
|---|---|---|
| 오디오 | 소리 — 무엇이 들릴지 | 200~5,000 Hz |
| 영상 | 공간 — 어디를 때렸는지 | 1~30 Hz |

영상은 소리를 만들지 않는다. **소리에 공간을 부여한다.**

### 2-3. 임팩트 해머 시험의 폰 버전

사용자가 물체를 여러 지점에 나눠 톡톡 치는 절차는 공학의 구조물 모드 측정 정석(impact hammer roving test)과 동일. 계측 장비가 하던 일을 폰으로 대체.

### 2-4. 학습 모델을 쓰지 않는다

전부 결정론적 신호처리. 학습 데이터·GPU·수렴 대기 없음. 단기 프로젝트에서 결정적 이점.

## 3. 파이프라인

```
[촬영] 폰 카메라+마이크, 물체를 5~10지점에서 톡톡 침
  ├ 오디오 → 타격 검출(트랜지언트) → 모드 추출(FFT 피크→f, 힐베르트 포락선 로그피팅→d, 타격별 피크 크기→a)
  └ 비디오 → 타격 위치 검출(타격 시점 프레임의 손끝 좌표) → 앵커 좌표
  ↓
[모드 정렬] 타격별 피크 리스트를 주파수 허용오차(±1~2%)로 클러스터링 → 전역 모드 세트 + 앵커별 진폭 벡터
  ↓
[.inst 파일] 사진 + 전역 모드(f,d) + 앵커(x,y,amps) — 수백 KB
  ↓
[플레이어] 탭 좌표 → 앵커 IDW 보간 → 모드별 진폭 → Web Audio 발화 + 파문/흔들림
  ↓
[공유] 링크 하나로 브라우저 즉시 연주 / 잼 세션
```

### 공간 보간 (확정: 넣는다)

- 진짜 난제는 보간이 아니라 **모드 정렬** — 타격 5개에서 나온 5개 피크 리스트에서 "1번 타격의 523Hz와 3번 타격의 527Hz는 같은 모드"를 묶는 것.
- **보간은 런타임 IDW(역거리 가중)**: 앵커들의 진폭 벡터만 저장, 탭 좌표에서 즉석 계산. 진폭 맵 이미지 불필요, 계산 비용 사실상 0, B의 구현은 함수 하나.
- 어떤 타격에서 안 보이는 모드는 a=0 (마디를 때린 것 — 물리적으로 정당).
- f·d는 클러스터 중앙값.

## 4. .inst 스키마 v0.2 (확정)

f·d는 물체 전역, a만 위치 종속 — 물리를 그대로 반영한 구조.

```json
{
  "version": "0.2",
  "meta": { "name": "머그컵", "created_at": "...", "quality_score": null },
  "image": { "src": "photo.jpg", "width": 1080, "height": 1440 },
  "modes": [
    { "id": "m1", "f": 523.3, "d": 1.8 },
    { "id": "m2", "f": 1247.1, "d": 3.2 },
    { "id": "m3", "f": 2210.4, "d": 5.1 }
  ],
  "anchors": [
    { "x": 0.42, "y": 0.31, "amps": [1.0, 0.6, 0.3] },
    { "x": 0.45, "y": 0.78, "amps": [0.2, 1.0, 0.7] }
  ],
  "mask": { "src": "mask.png", "optional": true },
  "playback": {
    "interp": "idw", "idw_power": 2,
    "master_gain": 0.8, "pitch_snap": null
  }
}
```

- 좌표 0~1 정규화 (화면 크기 독립).
- `amps`는 `modes` 순서 정렬.
- a는 상대값, 절대 음량은 `master_gain` (AGC 때문에 절대 진폭 신뢰 불가).
- 마스크 옵셔널 — 없으면 전체 탭 가능하되 앵커에서 멀수록 IDW가 자연히 소리를 줄임. 필요 시 사용자가 윤곽을 손가락으로 문지르는 방식 (SAM보다 1주 스코프에 적합).
- 스키마 변경은 두 사람 합의 + 버전 업으로만.

## 5. 연주 인터페이스 설계

**"사진 아무 데나 두드리기"는 연주가 아니라 탐색.** 6인치 화면에서 같은 지점을 리듬에 맞춰 정확히 반복 타격하는 건 불가능. → 탐색과 연주를 분리하는 3단계 전환.

1. **탐색**: 사진 전체가 터치 가능. 아무 데나 두드리면 그 지점 소리 + 파문. "입구는 맑고 바닥은 둔탁하네"를 스스로 발견 — 제품의 감동 포인트.
2. **고정**: 마음에 드는 지점을 길게 눌러 핫스팟 저장(최대 6개). 손가락보다 크게 자동 보정. "이 컵에서 내가 좋아하는 소리 네 개"를 고르며 물체가 악기가 됨.
3. **연주**: 화면 상하 분할. 위=사진, 아래=핫스팟 복제 패드. 패드를 치면 위쪽 해당 지점이 빛나고 떨림. 연주는 아래에서, 시각 연결은 위에서. 양손 엄지 리듬 가능.

### 음정 설계

- **물체 하나 = 한 음이 아니라 한 음색.** 모든 모드 주파수에 같은 비율을 곱하면 음정이 통째로 이동 — 물리적으로 "같은 재질·모양의 더 크거나 작은 물체"와 동일해 정직함.
- 연주 화면 축: **가로 = 타격 위치(음색), 세로 = 음정(도레미)**. 컵 하나로 멜로디 가능. 이게 없으면 드럼패드일 뿐.
- 기본 화면은 원음 한 줄, 음정 축은 펼쳐서 여는 방식 (처음부터 격자면 "샘플러 앱"으로 보임).
- **튜닝 스냅**: 기본 주파수를 가장 가까운 반음으로 스냅하되 **상위 모드 비율은 유지** (음정만 옮기고 음색 보존). 실물 모드는 비조화적(종·실로폰 계열)이라 스냅 없이는 합주가 불협으로 뭉개짐 — 합주 성립의 필수 조건.

### 손맛 인터랙션 (물리적으로 정당한 것만)

- **두드리기**: 임펄스. 세게 치면 저주파 모드 비중 증가.
- **누르기 = 음소거**: 짚은 지점에서 강한 모드의 감쇠를 올림. 실제 연주자가 손 대서 소리 죽이는 것과 동일 — 누르는 위치를 옮기며 연주하는 것 자체가 기술이 되어 숙련도가 생김.
- **문지르기**: 노이즈 지속 입력. 드래그 속도=강도, 위치=음색.
- **활 긋기**(보너스): 스틱-슬립으로 지속음.

### 감각을 속이는 두 가지 (필수 제약)

- **터치→소리 지연 30ms 이내.** 넘으면 뇌가 "가짜"로 판정. AudioContext 사전 언락, touchstart 기준 발화, 버퍼 최소화.
- **타격 순간 20ms 햅틱.** 물리적 저항 부재를 놀랄 만큼 잘 메움.

### 솔직한 우선순위

**핵심 루프는 연주가 아니라 채집.** 연주 UI는 GarageBand를 못 이김. 사람들이 쓰는 이유는 "내가 두드려서 찾아낸 소리". → 채집이 재밌고, 연주는 그 소리를 충분히 즐길 만큼만 좋으면 됨. 연주 결과를 루프로 저장·공유하는 경로는 열어둘 것.

## 6. 재미 루프와 가벼운 실용

### 재미 루프의 심장

앱이 채집 직후 **악기 점수**를 매김 ("모드 7개, 지속 3.2초 — 훌륭한 악기예요"). 사람들이 다음 물건을 찾아 집안을 돌아다니게 만드는 것. 어릴 때 모든 걸 두드려보던 행동의 부활.

- **잘 되는 물체**: 유리컵, 머그, 스테인리스 볼, 빈 병, 냄비뚜껑, 철제 선반, 자전거 프레임, 계단 난간, 라디에이터, 문틀, 나무 도마, 세라믹 화분 (단단·얇음·저감쇠).
- **안 되는 물체**: 쿠션, 카펫, 책, 흙, 두꺼운 벽 (고감쇠). 실패도 콘텐츠 — "왜 베개는 악기가 안 되는가"를 감쇠 그래프로 보여주면 물리 교육이 됨.

### 가벼운 실용 (확정: 이 셋만)

방향성: "쓸모없다는 생각만 안 들면 됨". 본격 기능(균열 검사 등)은 과함.

1. **나만의 알림음 공장** (최우선): 채집한 소리를 알림음/알람 파일로 내보내기. 구현 반나절, "쓸모없잖아"를 소멸시킴. 알림이 울릴 때마다 "이 소리 뭐야" → 바이럴.
2. **ASMR/백색소음 모드**: 채집 물체들을 낮은 음량 랜덤 재생. 리조네이터에 느린 랜덤 임펄스 — 거의 공짜 기능.
3. **소리 도감 수집욕**: 재질별 뱃지(유리 5종, 금속 5종…), 희귀 소리 판정. 포켓몬고가 쓸모를 안 따지게 만드는 구조.

참고: 균열 검사·잔량 측정·벽 스터드 찾기·드럼 튜너·가전 이상음·RT60 측정은 전부 같은 엔진("소리 지문을 저장하고 다시 재서 비교")의 파생으로 성립하지만, 이번 스코프에서는 확장 방향 한 줄로만 유지. 수박 숙성도 판별은 기존 앱·연구가 이미 존재하므로 채집 카테고리의 재미 요소로만.
진단류를 만들 경우의 원칙: 절대 안전 판정("안전합니다") 금지, **변화**만 말할 것("3주 전 대비 주파수 4% 하락, 전문가 점검 권장").

### 멀티플레이어 (확정: 잼 세션 하나만)

- **잼 세션**: 같은 링크 = 같은 방. 같은 물체 세트를 동시 연주, 서로의 터치가 파문으로 보이고 들림. **발표 데모의 본체.**
- 구현의 축복: WebSocket으로 터치 이벤트(좌표+세기)만 브로드캐스트, **소리는 각자 로컬 합성** — 오디오 스트리밍 불필요. 악기 파일 수백 KB라 방 입장 즉시.
- **동기화 환상 주의**: 네트워크 지연으로 완벽한 박자 합주는 불가능. 해결하려 들지 말고 프레이밍으로 회피 — 정확한 합주가 아니라 **풍경(soundscape)을 같이 만드는 감각**. 그러면 200ms 지연도 문제없음.
- 릴레이 작곡·배틀·랭킹은 스코프 밖. 협동 채집은 자연 발생 행동이지 기능이 아님.

## 7. 선행 연구와 차별점

| 선행 | 내용 | 차이 |
|---|---|---|
| MIT Interactive Dynamic Video (2015) | 영상 진동 모드 → 드래그 | **소리 없음**, 연구 데모 |
| Google Generative Image Dynamics (2023) | 학습 prior로 모션 생성 → 드래그 | **소리 없음**, 실제 물리 아닌 생성 |
| Visually Indicated Sounds 계열 | 영상에서 타격음 학습 예측 | 재생일 뿐 **연주 불가** |
| Modalys 등 물리 모델링 신스 | 모달 합성 가상 악기 | **실물 측정 아닌 수동 입력** |
| MIT Visual Microphone | 물체 진동에서 주변 소리 복원 | 방향 반대 (물체를 울리는 게 아님) |

**비어 있는 자리**: 실물을 폰으로 측정해 연주 가능한 악기로 만들고 링크로 공유하는 것.
**정직한 포지셔닝**: 코어 기술은 새롭지 않다. **조합과 제품화가 기여다.** 발표에서 숨기지 않는다.

## 8. 1주 로드맵 (클로드 맥스 2계정 풀가동)

### 전제

코드 생산량은 병목이 아님. 병목은 (1) **물리 검증** — 실물 두드리기는 클로드가 못 함, (2) 통합 지점의 손맛 튜닝, (3) 스코프 결정.

### 1주 스코프 조정

- ~~공간 보간 제거~~ → **복원 확정** (런타임 IDW + 모드 정렬로 구현).
- 위상 기반 시각 진동 워프 제거 → 파문 + 이미지 흔들기로 대체 (체감 90%, 비용 5%).
- 세그멘테이션: 옵셔널 (마스크 없이 IDW 감쇠로 대응, 필요 시 수동 문지르기).
- 최종 스코프: 채집(타격 검출+위치) → 모드 정렬 → IDW 연주(탭/음소거/음정 시프트) → 링크 공유 → 잼 세션 → 알림음 내보내기 → 도감.

### 분업 — 경계선은 .inst 파일

- **A (DSP+백엔드)**: .inst를 **만드는** 쪽 — 녹음 분석, 모드 추출·정렬, 처리 서버, 잼 세션 WebSocket, 알림음 렌더링.
- **B (프론트+제품)**: .inst를 **소비하는** 쪽 — 채집 UI, 연주 화면, Web Audio 리조네이터 뱅크, IDW, 공유 뷰어, 도감, 발표.
- 리조네이터 뱅크를 B에 준 이유: 합성은 .inst의 (f,d,a)만으로 프론트 단독 구동 가능하고, 30ms 지연 튜닝은 UI와 한 몸.

### 일자별

**D1 — 계약과 관문 절반**
- 공동(오전): .inst v0.2 확정, 레포·배포 세팅.
- A: 컵 녹음 → 추출 → 재합성 CLI. **추출 알고리즘 변형 3개 병렬 생성 후 실측 선발** (①FFT 피크+힐베르트 ②STFT 피크 추적 ③ESPRIT/Prony). 판정: 닮았는가 / 모드 수 5~20개 / **타격 간 f 안정성** (보간의 전제). + 모드 정렬 초기 버전.
- A 실물 작업: 유리컵·머그·냄비·도마 녹음. 같은 컵을 **서로 다른 5지점** 각 2~3회, 지점 위치 수동 기록. **AGC 끄기 필수** (감쇠값 오염 방지). 튜너 앱으로 기본 주파수 별도 측정 (유일한 정량 검증).
- B: 목 .inst(v0.2, 앵커 5개 — 위쪽 앵커는 고주파 크게, 아래쪽은 저주파 크게)로 연주 화면 + 리조네이터 뱅크 + IDW. 드래그 탭으로 음색이 굴러가는지 확인. 실기에서 지연 체감 검증 (모바일 오디오 언락은 데스크톱과 다름).
- 리조네이터 구현: OscillatorNode+GainNode에 setTargetAtTime 지수 감쇠 (바이쿼드+임펄스보다 디버깅 쉬움). AudioContext 사전 resume, touchstart 발화.
- **밤: 첫 관통** — A의 진짜 파라미터 + 수동 앵커 좌표를 B 화면에 꽂아, 화면 속 컵을 탭하면 낮에 녹음한 그 컵 소리가 남. 이후 6일의 확신이 여기서 나옴.
- 통과 기준: ①재합성이 원본과 유사 ②추출 f ≈ 튜너값 ③end-to-end 관통 ④실기 지연 체감 즉각.

**D2 — 채집 플로우**
- A: 타격 검출, 다중 타격 분리, 타격별 (f,d,a), 모드 정렬 완성, 처리 서버 API.
- B: 폰 촬영/녹음 UI, 타격 위치 검출 (자동이 하루 안에 안 되면 **사용자가 사진에서 직접 탭 지정** 폴백 — 오히려 UX가 명확할 수 있음), 업로드→처리→연주 연결.
- 관문: 내 폰으로 실물 컵을 채집해 그 자리에서 연주 + **서로 다른 두 곳을 탭하면 다른 소리**.

**D3 — 연주감과 물체 다양성**
- A: **물체 사냥이 주업무** (15~20종 실측, 지점 다양성 포함 — 컵은 잘 갈리는데 도마는 안 갈릴 수 있음, 그것도 데이터). AGC·반향 실데이터 확인. 알림음 렌더링 API.
- B: 핫스팟 저장/패드, 누르기=음소거, 음정 시프트(반음 스냅), 햅틱, 지연 튜닝.
- 관문: 재질 다른 3개 물체가 각자 다른 음색으로 구분됨.

**D4 — 공유와 잼 세션**
- A: WebSocket 방(터치 이벤트만 브로드캐스트), 방 생성/입장.
- B: 링크 뷰어(설치 없이 브라우저 즉시 연주), 남의 터치 파문, QR.
- 관문: **폰 두 대가 같은 링크에서 같은 컵을 두드리고 서로 보임.**

**D5 — 살 붙이기**
- A: 알림음 내보내기 완성, 잼 세션 부하 테스트(동시 50+ = 발표장 시뮬레이션), 서버 안정화.
- B: 소리 도감(카드+악기 점수+재질 뱃지), 온보딩(첫 채집까지 3분), 이펙트.
- 관문: 처음 보는 사람이 도움 없이 채집~연주 완주.

**D6 — 데모 리허설 (기능 동결)**
- 신규 기능 금지. 발표 물체 후보 10개 실측 → 3개 확정, 백업 .inst 저장.
- 발표장 조건(소음·와이파이) 리허설, 관객 동시 접속 실험, 통짜 리허설 2회.

**D7 — 발표**
- 최종 리허설 + 슬라이드. 라이브 채집 실패 시 백업 전환 스크립트 암기.

### 클로드 토큰 운용 원칙

- **선발전**: 중요 결정은 변형 여러 개 병렬 생성 → 실측 선발 ("하나 짜서 디버깅"이 아니라 "여럿 짜서 선발").
- **대기 시간 제로화**: 한 세션 구현 중 다른 세션에 다음 스펙·테스트·목 데이터 작성.
- **밤 사이 큐**: 리팩토링·테스트·엣지 케이스를 자기 전에 던지고 아침 리뷰.
- **문서 실시간화**: .inst 변경 시 양쪽 코드 동기화를 클로드에 맡겨 드리프트 방지.
- 반대로 **사람 시간은 클로드가 못 하는 곳에**: 실물 두드리기, 귀 판정, 손맛 튜닝, 스코프 자르기. (D3의 물체 사냥은 낭비가 아니라 핵심 일정.)
- 토큰이 남을 때의 함정은 "더 많은 기능". 1주 프로젝트는 더하기가 아니라 빼기 싸움.

## 10. 발표 시나리오 (5분)
